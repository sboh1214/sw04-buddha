# 03 마켓과 판정 · Market & Resolution

설계안 v0.2 · 2026-10-04

### 1. 시장의 정의

초기 시장은 YES/NO 이진 계약이다. Event는 실제 사건, Market은 판정 가능한 질문, Outcome은 결과, Position은 체결된 계약 보유다. 별도 Forecast 객체는 사용하지 않는다.

카테고리는 주 분류 하나, 태그는 여러 개를 허용한다. 관련 시장은 운영자가 연결한다. 다중 선택·수치형·조건부 시장은 후속이다.

### 2. 개설과 검수

운영자가 개설하고 다른 검수자가 규칙을 확인하는 방식을 기본안으로 한다. 사용자는 질문을 제안할 수 있으나 직접 상장하지 않는다.

필수 항목: 제목·배경·카테고리·태그, YES 조건, 기한까지 YES 불충족 시 NO 조건, 1차 출처·대체 출처 우선순위, 기준 시간대, 개장·거래 마감·예정 판정 시각, 지연·취소·무효 처리, 봇 예산·설정 버전.

이미 결과가 알려진 질문, 모호한 기준, 동일 조건의 중복 시장은 개설하지 않는다. 같은 사건의 다른 질문도 독립 판정 조건이 있어야 한다.

### 3. 생애주기

DRAFT → REVIEW → SCHEDULED → OPEN → CLOSED → PROVISIONAL → RESOLVED → SETTLING → SETTLED.

OPEN ↔ PAUSED는 전체 거래의 일시 중단이다. CLOSED 이후 거래를 재개하지 않는 것을 기본으로 한다. 결과 유형은 YES/NO/VOID로 상태와 별도 저장한다. 거래가 전혀 없던 시장은 CANCELLED로 종료할 수 있다.

개장 전에 규칙 버전과 유동성 설정을 고정한다. 시장 마감은 서버 시각 기준이며, 새 주문·잔여 대기 주문의 체결을 막고 미체결 예약을 해제한다. 체결과 마감은 순서화한다.

봇만 중단된 경우 사용자끼리의 거래는 OPEN 상태에서 계속 가능하다. 담보·원장 장애 또는 사건 선공개는 시장 전체 PAUSED 사유다.

### 4. 규칙과 시각

거래 마감과 결과 판정일은 다르다. 저장은 UTC, 표시는 사용자 시간대와 명시된 판정 기준 시간대를 제공한다.

예정 발표 전 선행 마감을 개설 시 설정한다. 조기 결과 공개를 확인하면 즉시 거래를 중단한다. 알고리즘이 뉴스 의미를 자동 판정한다고 가정하지 않는다.

출처가 늦으면 판정 대기로 유지하고 다음 검토 시각을 알린다. 예정보다 늦었다는 이유만으로 NO를 선언하지 않는다. 장기 지연·대체 출처·VOID 전환 기준을 개설 전에 정한다.

개장 후 문구 보충은 원래 의미를 바꾸지 않는 범위에서 버전·사유·알림을 기록한다. 실질 기준 변경은 거래를 멈추고 기존 규칙으로 판정 가능한지 검토하며, 불가능하면 사전 VOID 규칙을 적용한다.

### 5. 판정과 이의제기

운영 판정자가 출처·증거·수집시각·제안 결과를 등록하고 별도 검토자가 승인한다. 판정자는 이해관계를 신고하고 해당 시장 거래에서 배제하는 운영안을 사용한다.

잠정 결과 공개 후 24시간 이의 기간을 초기안으로 제안한다. 사용자는 근거 링크와 사유를 제출한다. 이의가 있으면 검토 완료까지 지급을 보류한다. 접수·검토·기각/수용 사유를 기록한다.

판정은 시장가격이나 다수 의견으로 결정하지 않는다. 결과 확정과 실제 지급 완료를 각각 표시한다.

### 6. 지급과 무효

YES 결과: YES 100 Coin, NO 0. NO 결과: 반대.

거래 후 정상 판정이 불가능한 VOID에는 계약별 50 Coin 지급을 기본 제안으로 한다. 이는 원금 환불이 아니며 매입가에 따라 손익이 생긴다. 개장 전 규칙에 명시하고 운영 승인 후 사용한다.

이전 체결을 구매자별로 되돌리면 이미 매도한 상대방과의 자산 흐름이 깨지므로 임의 원금 환불을 하지 않는다. 거래 없는 취소 시장은 주문 예약 해제와 봇 보유 쌍 소각으로 배정 자금을 회수한다.

### 7. 정산 무결성

마감 후 미체결 주문을 취소하고 보유 원장을 확정한다. market_id·resolution_version·position_id로 지급을 식별하며 반복 실행해도 한 번만 지급한다.

담보는 지급 중에도 예약한다. 부분 실패는 완료 건을 건드리지 않고 미완료 건부터 복구한다. 모든 지급과 계약 소멸을 대사한 뒤 SETTLED로 전환한다.

최종 지급 전 오류는 잠정 결과를 정정하고 이의 기한을 다시 제공한다. 최종 지급 후에는 자동 회수·음수 잔액을 만들지 않는다. 사건 검토, 정정 기록, 별도 승인된 보상으로 처리하고 원래 정산 이력을 보존한다.

### 8. 운영 화면·알림

개설 검수 목록, 마감 예정, 판정 대기·지연, 이의 접수, 정산 실패 목록을 제공한다. 수정·중단·판정·지급 작업의 담당자·시각·사유를 보존한다.

사용자는 규칙, 현재 상태, 지연 사유, 잠정·최종 결과, 출처, 이의 기한과 접수 링크를 확인할 수 있다.

### 9. 인수 조건

정상 YES/NO, 거래 전 취소, 거래 후 VOID, 조기 결과, 출처 지연, 판정 이의, 정산 중단·재시도, 지급 후 오류를 테스트한다. 스코어 계산은 정산 완료 조건에 포함하지 않는다.
