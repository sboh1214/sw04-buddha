# 02 거래와 화면 · Trading & Product UX

설계안 v0.2 · 2026-10-04

### 1. 거래만으로 참여한다

별도 YES/NO 투표나 확률 입력은 없다. YES/NO는 거래할 계약의 선택이며, 매수·매도 주문이 체결되어야 보유 포지션이 변한다. 주문만 제출한 상태는 참여 포지션으로 표시하지 않는다.

확률 슬라이더, My Forecast, Community Forecast, Forecast 수정 이력은 제품 범위에서 제거한다. 점수 계산은 미정이며 본 거래 흐름에 포함하지 않는다.

### 2. 정보 구조와 사용자 흐름

최상위는 시장 탐색, 커뮤니티, MY로 구성한다. 검색은 시장을 대상으로 하고 랭킹 메뉴는 점수 정책 결정 전 노출하지 않는다.

시장 탐색 → 상세에서 규칙·가격·호가 확인 → 계약과 매수/매도 선택 → 주문 확인 → 체결/대기 → MY에서 관리 → 중도 매도 또는 결과 정산.

비로그인 사용자는 시장·차트·호가·규칙·공개 토론을 볼 수 있다. 주문·댓글·관심 등록은 로그인 후 가능하다. 로그인 후 주문 입력은 복원하되 자동 제출하지 않는다.

### 3. 홈·검색

카드: 질문, 카테고리, 대표 시장가격, 가격 기준과 갱신시각, 마감, 상태, 사용자 참여자 수. 거래량은 실제 체결 대금 기준으로 양쪽을 중복 합산하지 않는다.

기본 분류: 전체/카테고리/관심 시장. 정렬: 운영 추천, 신규, 마감 임박. 거래량 순은 비정상 거래 제외 기준을 둔다. 개인화와 통합 사용자 검색은 후속이다.

검색은 제목·태그를 대상으로 상태·카테고리 필터를 제공한다. 결과 없음, 로딩, 네트워크 오류를 구분한다. 닫힌 시장도 상태 필터로 찾을 수 있다.

### 4. 시장 상세

질문·배경·규칙·출처·마감·예정 판정일, 가격 차트, YES/NO 호가, 최근 체결, 주문 패널, 내 포지션·대기 주문, 토론, 관련 시장을 제공한다.

데스크톱은 차트·호가와 주문 패널을 병렬 배치한다. 모바일은 요약과 차트 아래 호가·거래 내역을 전환하고 주문 패널을 별도 시트로 연다. 주문 확인에 필수인 가격·수량·금액은 접힌 상세 영역에 숨기지 않는다.

### 5. 가격과 확률 표시

대표 시장가격은 마지막 유효 체결을 YES 기준으로 환산한 값으로 제안한다. NO가 37에 체결되면 YES 기준 기록은 63이다. 시각을 항상 함께 표시한다.

첫 체결 전에는 ‘체결 없음’으로 표시하고 봇의 50% 초기 설정을 실제 체결 차트에 넣지 않는다. 시장가격은 실제 발생 확률의 보장이 아니다.

매수 버튼은 실제 최우선 매도호가, 매도는 실제 최우선 매수호가를 사용한다. 해당 방향 호가가 없으면 ‘호가 없음’으로 표시한다. 최근 체결가·호가·평균 체결가는 서로 다른 숫자다.

표시용 YES/NO 보완값은 합계 100이지만 YES 매수가와 NO 매수가의 합계가 반드시 100은 아니다. 스프레드가 있으므로 ‘매도 가격=100−동일 계약 매수가’로 계산하지 않는다.

차트는 유효 체결만 기록하고 무거래 구간은 마지막 체결 이후 갱신 없음이 드러나게 표시한다. 봇의 주문 변경을 체결로 기록하지 않는다. 변화량은 %p로 표기한다.

### 6. 주문 패널

계약 YES/NO → 매수/매도 → 즉시 거래/지정가 순으로 선택한다.

- 즉시 매수: 사용할 코인 또는 수량 입력. 가격 보호 한도를 포함한 IOC로 전송한다. 남은 부분은 취소하며, 입력 예산 전액 사용을 보장하지 않는다.
- 즉시 매도: 보유 수량 중 매도 수량 입력. 최소 허용 단가를 포함한 IOC로 전송한다.
- 지정가: 계약 수량·한도가격 입력. GTC로 미체결 잔량을 대기시키되 시장 마감 시 만료한다.
- 가격 보호 폭은 시장별 출시 설정이다. 주문 확인 화면에서 실제 최대 매수 단가/최소 매도 단가로 표시한다. 무제한 시장가는 제공하지 않는다.
- Post-only, 예약·조건부 주문, 레버리지, 공매도, Combo는 후속 또는 제외다.

확인 화면: 선택 계약, 주문 방식, 수량/예산, 예상 체결량, 평균가, 수수료, 예상 지불·수령, 가격 한도, 미체결 처리. 매수는 정답 시 총지급액과 순이익을 구분하고 오답 시 지급 0을 명시한다.

견적은 현재 호가의 예상치다. 서버 재검증에서 조건을 충족하는 부분만 체결하며 허용 가격을 자동 확대하지 않는다.

### 7. 주문 상태

접수 중 → 대기/부분 체결/전량 체결. 취소 완료·만료·거절을 별도 표시한다. 부분 체결 후 취소된 주문에도 체결 수량과 남은 취소 수량을 보존한다.

취소 요청 중에는 완료로 표시하지 않는다. 체결 알림이 먼저 도착하면 최종 서버 상태를 표시한다. 오류·재접속 시 동일 요청 ID로 조회하여 중복 주문을 막는다.

잔액 부족·보유량 부족·마감·호가 부족·가격 한도·일시 중단을 구분해 설명한다. 봇 공급 중단만으로 전체 시장을 종료 표시하지 않는다.

### 8. MY·포트폴리오

가용 코인, 주문 잠금 코인, 포지션을 분리한다. 포지션에는 YES/NO별 보유 수량, 매도 잠금 수량, 가중평균 매입가, 잔여 원가, 실현·미실현 손익을 표시한다. 양쪽 계약을 동시에 보유할 수 있다.

매입은 수량 가중평균 원가로 합산하고 매도는 같은 평균 원가로 처분 원가를 차감한다. 실현 손익=순매도 수령액−처분 원가, 정산 손익=지급액−잔여 원가다. 지급·재지급은 거래 수익으로 계산하지 않는다.

현재 보유가치는 최근 체결가 기준 참고 평가로 표시한다. 체결이 없으면 평가 불가, 오래된 체결이면 갱신시각을 표시한다. 실제 매도 가능액은 호가 깊이로 별도 계산하며 물량이 부족하면 일부 수량만 가능한 것으로 보여준다.

MY 탭: 보유 계약, 대기 주문, 거래·정산 이력, 지갑, 내 글, 알림·설정. 공개 프로필과 개인 자산 화면은 구분한다.

### 9. 가입·온보딩

인증·약관 동의·닉네임 설정 → 초기 코인 1회 지급 → 시장 탐색. 관심 카테고리는 건너뛸 수 있다. 첫 주문에서 계약 지급액, 지정가 대기, 부분 체결, 가격 보호를 짧게 설명한다.

계정 제한 시 신규 주문은 막되 잔액·기록·이의제기 경로는 유지한다. 탈퇴 시 대기 주문을 취소하고 미정산 계약 처리 안내 후 계정 폐쇄 절차를 진행한다. 보존기간은 실제 운영 정책 설정으로 관리한다.

### 10. 인수 조건

YES/NO·매수/매도 네 경로, 금액/수량, 부분 체결 후 취소, 마감 경합, 새로고침·재접속, 호가 없음, 모바일 주문 확인을 검증한다.

독립 확률 입력이 어느 화면에도 없고, 매수 입력값이 개인 신념 확률로 저장되지 않아야 한다.
